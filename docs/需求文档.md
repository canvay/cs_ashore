# 「申论黑话」需求文档（PRD）

> 版本：v1.0
> 日期：2026-11-24
> 产品阶段：V1 MVP（纯前端、零服务端、离线可用）
> 配套文档：《技术方案》v0.2
> 覆盖端：微信小程序 + Web（响应式，含移动浏览器）

---

## 1. 背景与目标

### 1.1 背景问题
申论作答的核心断层：给定材料是"口语大白话"（如"村里大事小情大家一起商量"），而答案要求"规范表述"（如"民主协商、村民自治"）。备考者普遍缺乏一套系统的"口语 → 规范词"积累工具，现状是：
- 翻教材零散摘抄，无检索能力
- 培训机构资料分散在讲义/PDF 里，无法随时练习
- 考前突击时想不起来某个场景该用什么规范词

### 1.2 产品定义
一个**申论规范词（黑话）词典 + 自测练习工具**：查得到、记得住、离线可用、打开即用。

### 1.3 版本目标与成功指标

| 目标 | 指标 | 目标值 |
|---|---|---|
| 验证需求 | 小程序 7 日留存（微信平台自带统计） | ≥ 15% |
| 验证使用深度 | 人均单日使用时长 / 人均练习次数 | ≥ 3 分钟 / ≥ 2 次 |
| 验证获客 | 上线 1 个月内小程序累计打开用户 | ≥ 1000 |
| 内容质量 | 词条准确性投诉（用户反馈渠道） | 0 起原则性错误 |

> 无服务端 → 全部依赖微信小程序数据助手 & Web 端静态统计（Umami/GA 可选），不追求精确漏斗。

### 1.4 目标用户
- **主用户**：国考/省考/事业编备考者，以 20-30 岁在职/应届为主，碎片时间用手机学习
- **典型场景**：
  1. 做申论题时卡壳："材料这段口语该翻译成什么规范词？" → 立刻查
  2. 通勤/睡前刷题碎片时间 → 翻卡自测
  3. 考前冲刺 → 按主题分类快速过一遍高频词
- **使用设备**：手机为主（>90%），PC 为辅（做申论套题时桌面端顺手查）

## 2. 功能需求

功能总览与优先级（P0 = V1 必须，P1 = V1 尽量，P2 = 明确不做）：

| # | 功能 | 优先级 |
|---|---|---|
| F1 | 词典搜索 | P0 |
| F2 | 分类浏览 | P0 |
| F3 | 词条详情 | P0 |
| F4 | 翻卡练习 | P0 |
| F5 | 收藏与掌握标记 | P0 |
| F6 | 本地学习统计 | P1 |
| F7 | 设置（字号/清除数据） | P1 |
| F8 | 词条反馈纠错 | P1 |
| F9 | 用户账号/跨端同步 | P2（不做） |
| F10 | UGC 添加自定义词条 | P2（不做） |

### F1 词典搜索（P0）

| 项 | 说明 |
|---|---|
| 输入 | 关键词，可命中：口语表述、规范词、标签、拼音（支持全拼/首字母，如 `mzxt` → 民主协商） |
| 行为 | 输入即时过滤（≤200ms 出结果），无网络依赖 |
| 结果 | 词条列表（规范词 + 第一条口语表述摘要 + 分类标签），按相关度排序：规范词精确命中 > 口语命中 > 标签/拼音命中 |
| 空态 | "没有找到"{关键词}"，换个说法试试"+ 展示该分类下随机 3 条词条 |
| 热词推荐 | 搜索框聚焦时展示高频推荐词（按数据包内置热度排序，非动态统计） |
| 历史 | 本地保存最近 10 条搜索历史，可单删/清空 |

### F2 分类浏览（P0）

| 项 | 说明 |
|---|---|
| 分类体系 | 数据包内置一级主题分类（首批：基层治理、产业发展、生态环保、文化建设、民生保障、改革创新、法治建设、应急管理与基层减负），每分类展示词条数 |
| 列表页 | 分类 → 词条列表（默认按内置热度排序，可切"按收录顺序"） |
| 快捷入口 | "高频 100"精选合集（数据包内置标记 `featured: true` 的前 100 条） |

### F3 词条详情（P0）

页面信息结构（自上而下）：
1. **规范词**（大字标题）+ 分类/标签
2. **口语表述对照**：材料原文说法列表（逐条对照展示）
3. **适用场景**：一句话说明用于哪类题型/主题
4. **真题例句**：出处（年份+考试名）+ 例句，例句中规范词高亮
5. **操作**：收藏/取消收藏、标记未掌握、加入练习、相关词条跳转

### F4 翻卡练习（P0）

| 项 | 说明 |
|---|---|
| 出题范围 | 单个分类 / "高频 100" / 仅"未掌握"词条，三种入口 |
| 模式 | 正面口语表述（可多条轮换）→ 用户回忆 → 翻卡看规范词 → 自评"会了 / 不会" |
| 队列 | "不会"的词条重新入队（本次练习内循环，间隔 ≥3 张卡），"会了"出队；一轮结束 = 队列清空 |
| 轮次报告 | 正确率、用时、未掌握清单（一键加入"未掌握"） |
| 进度中断 | 退出练习保留队列进度（本地存储），下次进入可继续 |

### F5 收藏与掌握标记（P0）

- 收藏夹独立页，按分类分组展示，支持取消收藏
- "未掌握"标记独立清单，是 F4 练习的默认入口之一
- 全部存本地（小程序 storage / Web localStorage），**无账号，换设备不迁移**（页面需有文案说明）

### F6 本地学习统计（P1）

- 端内展示：累计查询次数、练习轮数、总正确率、已掌握/未掌握词条数、连续学习天数（本地日历）
- 仅本地展示，不上报；数据清除入口在设置页

### F7 设置（P1）

- 字号调整（标准/大，服务中老年备考人群）
- 清除搜索历史 / 清除全部本地数据（二次确认）
- 数据版本号展示（如 `shenlun-data v2026.11.24 · 512 词条`）
- 关于/免责声明（内容为公开表述归纳整理，真题出处仅标注年份与考试名称）

### F8 词条反馈纠错（P1）

- 词条详情页"纠错"入口 → 展示内置反馈二维码（微信/QQ 群或邮箱）
- v1 不做端内表单提交（无服务端），二维码图片即可

## 3. 信息架构与页面清单

### 3.1 小程序端（Tab 结构）

```
┌ Tab1 查词 ── 搜索页（搜索框/热词/历史）
│              └─ 搜索结果 → 词条详情
├ Tab2 分类 ── 分类列表 → 词条列表 → 词条详情
│              └─ 高频100 入口
├ Tab3 练习 ── 练习首页（范围选择/未掌握入口/上次进度）
│              └─ 翻卡练习页 → 轮次报告页
├ Tab4 收藏 ── 收藏夹（分组列表）
│              └─ 未掌握清单 → 词条详情
└ 我的    ── 本地统计 / 设置 / 反馈 / 关于
```

### 3.2 Web 端（响应式）

| 视口 | 布局 |
|---|---|
| `<768px`（移动浏览器/PWA） | 与小程序一致：底部 Tab + 页面栈，保证两端交互习惯统一 |
| `≥768px` | 三栏：左侧分类树 + 中间词条列表 + 右侧词条详情（点击列表不跳页，右栏刷新）；练习模式居中翻卡（大卡更适合键盘快捷键：空格翻卡、←→会了/不会） |

路由（SSG 预渲染，保证 SEO）：
- `/`（搜索首页）· `/categories` · `/categories/[id]` · `/entries/[id]` · `/practice` · `/favorites`
- 词条详情页全部预渲染为静态 HTML，每条一个 URL → 搜索引擎收录长尾词（如"申论 规范词 民主协商"）

## 4. 数据需求

### 4.1 词条字段（与《技术方案》4.1 对齐）

| 字段 | 必填 | 说明 |
|---|---|---|
| id | ✓ | 全局唯一，`{分类缩写}-{序号}` |
| colloquial | ✓ | 口语/材料表述，1-5 条 |
| standard | ✓ | 规范词，1-4 个（顿号分隔展示） |
| category | ✓ | 一级分类 |
| tags | - | 0-6 个 |
| usage | ✓ | 适用场景一句话 |
| examples | - | 真题例句（source 仅标注"2024 国考副省级"级别，不引原文段落） |
| related | - | 相关联词条 id |
| featured | - | 高频 100 标记 |
| heat | - | 内置热度（用于排序与热词推荐） |

### 4.2 V1 数据规模与质量标准

| 项 | 要求 |
|---|---|
| 上线门槛 | **≥ 300 条**（低于 100 条不值得发布），其中"高频 100"必须有 100 条 |
| 覆盖 | 8 个一级分类每类 ≥ 25 条 |
| 质量红线 | 规范词必须是政府公文/权威媒体/主流申论教材中的通用表述；口语表述须来自真实材料风格；**禁止直接复制任何培训机构教材原文段落** |
| 校验 | 构建时 zod 强校验：id 唯一、必填非空、related/examples 引用存在性、分类白名单 |
| 上线前校对 | 全量人工核对一遍（含错别字、规范词准确性）；标注来源可追溯（编辑用的 source 字段不上端） |

### 4.3 数据更新节奏
- V1 期间每 2 周一版：补充词条 + 修正纠错反馈
- 小程序发版更新（提前积累纠错，攒批次提审）；Web 随时重部署即时生效

## 5. 非功能需求

| 维度 | 要求 |
|---|---|
| 离线 | 小程序首开后全功能离线可用；Web 第二次访问起 Service Worker 全缓存，离线可查词/练习（在线时静默更新数据版本） |
| 响应式 | Web 320px-1920px 无横向滚动、无布局断裂；断点行为见 3.2 |
| 性能 | 搜索出结果 ≤ 200ms（千级数据端内检索）；小程序首屏可交互 ≤ 1.5s；Web LCP ≤ 2.5s（4G） |
| 包体 | 小程序主包 ≤ 1.5MB（预留余量），数据构建脚本输出体积报告，超限告警/拆分包 |
| 兼容 | 小程序基础库 ≥ 2.30；Web：Chrome/Safari/微信内置浏览器近 2 年主流版本 |
| 可访问性 | 详情页支持字号放大；规范词大字号展示；Web 端语义化标签（利于 SEO 也利于读屏） |
| 隐私 | 不收集任何用户数据、无任何上报埋点（统计仅用微信平台自带数据助手）；设置页明示"所有记录仅存本机" |
| 安全 | 纯静态资源，无后端攻击面；内容自审规避敏感表述 |

## 6. 边界与异常场景

| 场景 | 行为 |
|---|---|
| 搜索无结果 | 空态文案 + 随机推荐 3 条（见 F1） |
| 未掌握清单为空时进练习 | 提示"先去查几个词或练一轮"，提供"高频 100"快捷入口 |
| 练习中途退出 | 保存队列进度；重新进入询问"继续上次 / 重新开始" |
| 收藏词条在数据更新后被移除 | 静默剔除并在收藏页顶部提示"2 条词条已下架" |
| 本地存储读写失败（极端） | 功能降级为内存态，提示但不崩溃 |
| Web 弱网/无网首访 | Service Worker 未就绪时正常在线加载，无特殊处理 |

## 7. 验收标准（V1 上线清单）

- [ ] 全部 P0 功能两端可用，P1 功能至少小程序端可用
- [ ] 词条 ≥ 300 条，构建校验 0 报错，人工校对完成
- [ ] 小程序主包 ≤ 1.5MB，审核通过发布
- [ ] Web 静态导出部署成功，词条详情页可被搜索引擎抓取（robots 允许 + sitemap）
- [ ] PWA 离线自测通过（断网查词/练习正常）
- [ ] 断点 375 / 768 / 1440 三档走查无布局问题
- [ ] 设置页可清除全部本地数据

## 9. 明确不做（V1 范围外，防止范围蔓延）

- 用户注册/登录、跨端同步、云备份
- UGC（自定义词条、笔记、社区分享）
- 服务端、数据库、任何动态 API
- 原生 App（iOS/Android）
- 行测/其他科目工具（V2 规划，见技术方案第 7 节演进路线）
- 数据 CDN 热更新（v1 用发版更新）
