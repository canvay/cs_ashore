## 1. 产品定位（MVP）

### 1.1 第一个版本只做一件事：「申论黑话」工具

申论作答的痛点是"材料里是口语大白话，答案要写规范表述"（俗称申论黑话/规范词）。本工具就是一个**口语 → 规范词的转换词典 + 练习器**：

| 功能 | 说明 |
|---|---|
| 词典查询 | 按关键词搜索口语表述或规范词，如搜"村里人都能发表意见" → "村民自治/民主协商" |
| 分类浏览 | 按主题分类：基层治理、产业发展、生态环保、文化建设、民生保障… |
| 词条详情 | 口语材料表述 ↔ 规范词对照、适用场景、真题例句出处 |
| 专项练习 | 口语→规范词的自测模式（显示口语，回忆规范词，翻卡核对） |
| 收藏/标记 | 本地收藏高频词条、标记"未掌握"（存 localStorage / 小程序 storage） |
| 学习统计 | 本地记录查询/练习次数（纯端内，无账号） |

### 1.2 明确不做（v1 范围外）
- ❌ 无用户体系、无服务端、无数据库
- ❌ 无 UGC（分享/评论/上传）
- ❌ 无 Web 与小程序之间的数据同步（各端本地存储）

> 架构上保留演进空间：后续加工具模块（如"行测错题本""数资公式卡""时政每日一练"）复用同一套纯前端模式；等需要账号/同步/社区时再引入 serverless 后端（见 7. 演进路线）。

## 2. 端与发布形态

| 端 | 形态 | 说明 |
|---|---|---|
| 微信小程序 | 微信原生开发（TypeScript），数据经 esbuild 打成 CJS 同步进包体 | **个人主体即可发布**（工具类目，无需企业资质）；下载后完全离线可用；无需配置任何合法域名 |
| Web | Vite + React 19 + HeroUI + Tailwind CSS 4（SPA） | 静态文件托管到免费/廉价静态托管；响应式布局（SEO 是后续获客抓手，必要时再评估 SSG） |
| 移动端 | = 响应式 Web（PWA 可添加到主屏） | 暂不做原生 App；后续有推送/离线包更新需求再评估 |

### 离线能力设计
- **小程序端**：数据打进包体（主包限 2MB，分包单包限 2MB、总包 30MB），首次打开即全量可用，天然离线。
- **Web 端**：SPA 静态托管；PWA/离线缓存作为后续增强项（manifest + Service Worker）。

## 3. 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 包管理 | **pnpm** workspace monorepo | `packageManager` 锁版本；构建类包用 `onlyBuiltDependencies` 放行 |
| Web | **Vite 6 + React 19 + HeroUI v3 + Tailwind CSS 4** | HeroUI（原 NextUI）基于 React Aria + Tailwind v4，主题用 CSS 变量定制；Tailwind 断点做响应式 |
| 小程序 | **微信原生 + TypeScript**（`miniprogram-api-typings`） | 多端分开实现，各端用各端最顺手的方案；界面为纯自定义布局，无需组件库 |
| 数据 | **TypeScript/JSON 数据包**（独立 package） | 题库数据单一来源；Web 直接 import workspace 包，小程序由 `scripts/build-miniprogram-data.mjs`（esbuild → CJS 单文件）同步到 `utils/` |
| 搜索 | 端内本地搜索 | 数据量小（千级词条），简单方案：构建时预建倒排索引/拼音索引，端内 fuse.js 或自写打分即可，无需服务端 |
| 状态 | localStorage（Web）/ wx storage（小程序） | 收藏/练习记录各端本地持久化 |
| 后端 | **无** | 数据更新 = 重新发布静态站 / 小程序提审 |

### Monorepo 结构

```
cs_ashore/
├─ apps/
│  ├─ web/            # Vite + React 19 + HeroUI SPA（响应式，兼顾 PC/移动）
│  └─ miniprogram/    # 微信原生小程序（TypeScript）
├─ packages/
│  ├─ heihua-data/    # 题库数据包：TS 源 → build 脚本 → dist（ESM）+ 小程序 CJS 同步
│  ├─ core/           # 业务逻辑：搜索、练习出题、本地存储适配、类型定义（规划中）
│  └─ ui/             # 跨端纯组件（词条卡片、翻卡练习、搜索框）（规划中）
├─ docs/
├─ pnpm-workspace.yaml
└─ package.json
```

## 4. 数据设计（核心资产）

### 4.1 词条 schema

```yaml
# packages/shenlun-data/data/entries/基层治理.yaml
- id: jczl-001
  colloquial:            # 口语/材料原文表述（可多个）
    - 村里大事小情大家一起商量
    - 村民都能参与决策
  standard: 民主协商、村民自治   # 规范词（黑话）
  category: 基层治理
  tags: [自治, 协商, 网格化]
  usage: 常用于基层治理/乡村振兴主题的对策题   # 适用场景
  examples:                    # 真题例句出处
    - source: 2024 国考申论副省级
      sentence: 推行"板凳议事会"，让村民议事有平台
  related: [jczl-014, jczl-022] # 相关联词条
```

### 4.2 构建流水线（`shenlun-data` 包内）
1. `data/**/*.yaml` 人工编辑（支持校验重复 id、必填字段）
2. `pnpm build`：zod 校验 → 生成 `dist/entries.json`（全量）+ `dist/index.json`（分词/拼音倒排索引）+ 分类清单
3. 端上按需 import；数据版本号写入 `dist/meta.json`，页面展示"数据版本"

### 4.3 数据规模预估与包体
- 1000 条词条 ≈ 300-500KB（压缩后 ~120KB），小程序可整体放主包；超 2MB 再拆分包。
- 数据更新的发布方式：Web 直接重新部署静态站（即时生效）；小程序走提审发版（1-2 天审核）。**数据以月/周为单位更新，完全够用。**
- （可选增强，仍无服务端）后续把数据 JSON 放到静态 CDN，端上启动时拉取比对版本号，命中新版则替换本地缓存——实现"不发版更新数据"。v1 不做。

## 5. 响应式设计（Web 端）

- 移动优先，Tailwind 断点：
  - `<768px`：底部 Tab（查词/分类/练习/收藏），复用小程序交互习惯
  - `≥768px`：左侧分类树 + 中间词条列表 + 右侧词条详情三栏
- 词条卡片、翻卡练习做成同一数据驱动的 compact/wide 两套布局，小程序直接复用 compact。
- PWA manifest + Service Worker：移动浏览器可"添加到主屏幕"，离线可用。

## 6. 部署与成本

| 项 | 方案 | 成本 |
|---|---|---|
| Web 静态托管 | 初期：**Cloudflare Pages / Vercel / GitHub Pages（免费）**；若国内访问慢，迁 CloudBase 静态托管或 EdgeOne Pages（按流量几元/月） | ¥0 - 10/月 |
| 域名 | 可选；自定义域名+备案仅为了 SEO 收录和品牌，**无 API 所以不强制备案** | ¥60/年（可选） |
| 小程序 | 个人主体免费注册，`miniprogram-ci` 或 IDE 上传提审 | ¥0 |
| 数据/代码仓库 | GitHub 私有仓库 | ¥0 |
| **合计** | | **≈ ¥0 - 10/月** |

CI/CD：GitHub Actions — push 即跑构建 → 自动部署静态站；小程序构建产物用 miniprogram-ci 上传体验版。

## 7. 演进路线

| 阶段 | 内容 |
|---|---|
| V1（现在） | 「申论黑话」单工具：查词/分类/练习/收藏，小程序 + 响应式 Web，纯前端离线 |
| V1.x | 补充词条数据；增加"时政热词""官方表述库"等同类数据包（复用同一数据 schema）；数据 CDN 热更新 |
| V2 | 多工具模块化（错题本、公式卡、模考工具）——仍是纯前端 + 本地存储 |
| V3（有增长验证后） | 引入 serverless（微信云托管）：账号体系、跨端同步、社区分享、题库服务——回到 v0.1 文档的架构，届时已有用户数据支撑成本决策 |

> 这条路线的本质：**用零成本工具验证获客与留存，把服务端投入推迟到被验证之后。**

## 8. 风险与要点

| 风险 | 对策 |
|---|---|
| 数据质量决定产品上限 | schema 强校验 + 词条来源标注；先攒 300-500 条高质量词条再上线 |
| 小程序个人主体限制 | 工具类目可用；不能开通支付/部分类目，v1 无影响 |
| 小程序主包 2MB 限制 | 数据包构建时统计体积告警；超限自动拆分包 |
| Web 托管国内访问速度 | 先免费托管上线观察；慢则切 CloudBase/EdgeOne（数据与构建产物是标准静态文件，迁移零成本） |
| 无账号 → 换设备丢收藏 | v1 接受；V3 加账号后做导出/同步 |
| 申论内容版权 | 词条为常见规范表述的整理归纳，标注真题出处需注明年份题名，避免直接复制培训机构教材原文 |
